# 问题登记簿（Issue Registry）

本文件登记 GEE AI 助手扩展已确认但尚未修复的缺陷，作为修复工作的基线清单。

## 登记模板

每条登记应包含以下字段：

```
### ISS-XXX 标题
- 编号：ISS-XXX
- 标题：<一句话概括>
- 现象：<用户可观察到的异常表现>
- 复现步骤：<触发该问题的最小步骤序列>
- 控制台报错：<相关报错原文，若无则写「无」>
- 所在层：<UI 层 / 内容脚本层 / 页面桥接层 / 服务层(service worker) / 共享库层(lib)>
- 状态：待修复 | 修复中 | 已修复 | 已验证 | 不修复
```

## 已登记条目

### ISS-001 多围栏代码块提取可能取错块
- 编号：ISS-001
- 标题：多围栏代码块提取可能取错块
- 现象：当模型回复包含多个 ``` 围栏代码块时，代码候选提取可能选中非目标块（如示例片段而非完整脚本），导致「应用到编辑器」的内容不符合预期。
- 复现步骤：让模型输出包含多个围栏代码块的回复（如先给一段示例、再给完整脚本），触发代码提取逻辑，观察被选中的块。
- 控制台报错：无
- 所在层：共享库层（lib/response.js）
- 状态：已修复

### ISS-002 对话上下文截断可能以 assistant 消息开头
- 编号：ISS-002
- 标题：对话上下文截断可能以 assistant 消息开头
- 现象：对话历史按长度截断时，截断点可能落在 assistant 消息处，使发送给模型的上下文以 assistant 消息开头，破坏 user/assistant 交替约定，可能导致 API 报错或模型行为异常。
- 复现步骤：构造足够长的对话历史触发上下文截断，检查截断后消息序列的首条消息角色。
- 控制台报错：视 API 返回而定（可能为消息顺序非法类报错）
- 所在层：UI 层（sidepanel.js，纯函数提取至 lib/conversation.js）
- 状态：已修复

### ISS-003 带后缀的 DeepSeek V4 模型名静默降级为非流式
- 编号：ISS-003
- 标题：带后缀的 DeepSeek V4 模型名静默降级为非流式
- 现象：模型名识别逻辑对带后缀的 DeepSeek V4 模型名（如 `deepseek-v4-xxx`）匹配失败，导致本应走流式路径的请求静默降级为非流式，用户无感知。
- 复现步骤：在设置中填入带后缀的 DeepSeek V4 模型名，发起请求，观察实际请求路径是否为流式。
- 控制台报错：无
- 所在层：共享库层（lib/api.js）
- 状态：已修复

### ISS-004 流式响应只有 reasoning 无 content 时报错措辞误导
- 编号：ISS-004
- 标题：流式响应只有 reasoning 无 content 时报错措辞误导
- 现象：流式响应中仅包含 reasoning（思考过程）而最终 content 为空时，错误提示措辞具有误导性（如提示网络/API 失败），用户无法判断真实原因。
- 复现步骤：触发一次模型仅输出 reasoning 而未产出 content 的流式请求（如 reasoning_effort 高且问题在思考阶段被截断），观察错误提示。
- 控制台报错：无（为应用内误导性提示，非运行时报错）
- 所在层：服务层（service-worker.js）
- 状态：已修复

### ISS-005 侧栏初始化失败后静默锁死

### ISS-007 侧栏首次加载 eventsBound TDZ 错误导致全界面失效
- 编号：ISS-007
- 标题：侧栏首次加载 eventsBound TDZ 错误导致全界面失效
- 现象：每次新开侧栏必现 `Cannot access 'eventsBound' before initialization`，全界面事件绑定失效（所有按钮/表单无响应），用户必须点击「重试初始化」才能恢复。

- 控制台报错：`Uncaught ReferenceError: Cannot access 'eventsBound' before initialization`
- 所在层：UI 层（sidepanel.js 顶层执行顺序：顶层 `initialize()` 调用早于 `let eventsBound` 声明，触发暂时性死区 TDZ）
- 状态：已修复

### ISS-008 计划阶段模型提前返回围栏代码导致报错
- 编号：ISS-008
- 标题：计划阶段模型提前返回围栏代码导致报错
- 现象：计划模式的规划/澄清阶段，模型有时提前返回围栏代码块（如 ```javascript），计划解析直接抛出原始 JSON 解析错误，用户看到难懂的报错且不知道如何恢复；提示词层面也缺少对“计划阶段禁止产出代码”的明确约束。
- 复现步骤：在计划模式下发送需求，当模型在计划轮返回含围栏代码块且不含有效计划 JSON 的内容时即可触发（可用单测构造：计划轮响应仅含 ```javascript 代码块）。
- 控制台报错：无未捕获异常；聊天区出现原始解析错误文案（如「模型最终内容不是有效的结构化 JSON…Plan response must contain a JSON object.」）
- 所在层：共享库层（lib/plan.js 计划解析、lib/orchestrator.js 计划轮链路与计划系统提示词）
- 状态：已修复

### ISS-009 计划卡选项勾选状态不保留且重复发送
- 编号：ISS-009
- 标题：计划卡选项勾选状态不保留且重复发送
- 现象：计划卡中澄清问题的选项勾选后，状态没有保持在卡片上（计划卡每次重渲染都丢失勾选样式）；用户因看不到已选状态再次点击，选项答案块会被再次注入聊天输入框并随下一条消息重复提交。
- 复现步骤：计划模式下进入澄清阶段，勾选某个选项并发送；等待新一轮计划卡渲染后观察选项恢复为未选状态，再次点击同一选项即可观察到重复注入/重复提交。
- 控制台报错：无
- 所在层：UI 层（sidepanel.js 计划卡选项渲染与点击事件）与共享库层（lib/ui.js 答案块标记）
- 状态：已修复

### ISS-010 队列徽标删除后不刷新
- 编号：ISS-010
- 标题：队列徽标删除后不刷新
- 现象：非忙碌状态下删除消息队列中的待发送消息后，侧栏 turnStateBadge 仍显示「N 条待发送」旧文案，直到下一次忙碌状态切换才刷新；入队/清空/drain 后徽标同样可能与实际队列长度不同步。
- 复现步骤：忙碌时入队至少一条后续消息，等待当前任务结束（徽标显示「1 条待发送」）；在队列面板点击「删除」移除该消息，观察徽标文案不变，直至下一次忙碌切换才更新。
- 控制台报错：无
- 所在层：UI 层（sidepanel.js：徽标文案仅在 setBusy 中内联计算，队列变更路径 renderMessageQueue 未同步刷新徽标）
- 状态：已修复

### ISS-011 上传 Shapefile 功能交付记录（含云端上传可行性调研结论与安全边界修订）
- 编号：ISS-011
- 标题：上传 Shapefile 功能交付记录（含云端上传可行性调研结论与安全边界修订）
- 现象：（功能记录，非缺陷）侧栏「资产 / 任务」面板头部新增「上传 Shapefile」入口，支持把整套 shapefile（必需 `.shp`/`.shx`/`.dbf`，可选 `.prj`/`.cpg`）入库为云端 Table 资产；云端不可用时经确认后降级为本地 GeoJSON 条目（「SHP·本地」），仍可注入脚本与注入对话。
- 复现步骤：（使用步骤）点击「上传 Shapefile」→ 选择一整套 shapefile → 满足云端条件（Code Editor 页面 + 已配置 OAuth 客户端与项目）时自动走云端直传，否则经确认后走本地解析降级。
- 控制台报错：无（同名云端资产冲突时上传报错提示改名，属预期行为）
- 所在层：UI 层（sidepanel.js）、页面桥接层（page-bridge.js 字节暂存通道）、服务层（service-worker.js）、共享库层（lib/shapefile.js 本地解析、lib/gee-rest.js 资产入库）
- 状态：已验证
- 调研结论与取舍：公开 Earth Engine REST 接口不支持字节直传入库（无公开 multipart 上传端点），Code Editor 页面的字节上传通道（`geturl` + `_ah/upload`）为会话鉴权且未文档化；因此方案取舍为——字节暂存段借用页面会话（与脚本注入同一 MAIN world 桥接机制），入库段调用公开标准 `table:import` REST（扩展自有 `earthengine` 范围 Bearer 令牌），形成「云端主路径 + 本地降级」双路径。
- 风险与边界：暂存通道属未文档化接口，可能随 Google 变更失效，失效时功能自动引导降级；用户已明确批准修订 README 安全边界（原「绝不复用网页令牌/Cookie/XSRF」）：扩展不存储、不导出、不读取任何 Cookie/XSRF 凭证明文，仅在页面内发起带凭证请求。上限：云端直传整套 8MB；本地解析整套 32MB、要素 50000、注入片段 1MB；仅 2D 点/线/面（Z 降维）、dBase III 属性；`.prj` 非 EPSG:4326 拒绝（不重投影）。详见 README「上传 Shapefile」「安全边界」「已知限制」各节。

### ISS-012 401 整链重试复用同一 requestId（权衡接受，暂不修复）
- 编号：ISS-012
- 标题：GEE REST 401 重新授权后的整链重试复用原 requestId
- 现象：`runGeeRestCall` 在 401 后重新授权并重试整条调用链（import 链含 table:import + LRO 轮询），两次尝试共用同一 requestId/abort 簿记；极端窗口内（第一次尝试进行中触发 abort 且恰逢 401 重试）abort 语义可能与重试链交叠。
- 复现步骤：构造首次 GEE REST 调用返回 401 触发重新授权重试，并在同一 requestId 上同时发起 abort。
- 控制台报错：无
- 所在层：服务层（service-worker.js runGeeRestCall / geeRestImportRequest）
- 状态：不修复（v0.4.x 复审建议项 4：触发条件苛刻且现有测试已背书整链重试语义，权衡后保留现状；如后续出现实际 abort 竞态报告再引入重试级 requestId 去重）

### ISS-013 生成代码易触发 GEE 运行时报错，且 Console 报错缺乏针对性诊断

- 所在层：共享库层（lib/plan.js validateTemporalCoverage 静态数据集豁免与修订轮次兜底）、编排层（lib/orchestrator.js 两套规划提示词追加静态数据集不参与时间覆盖校验条款）
